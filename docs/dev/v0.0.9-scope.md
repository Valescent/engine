# v0.0.9 scope: Far View

**Status:** Implementation complete - storage, renderer, streaming/mesher/light hardening, horizon,
and the level-1/2 and level-3/4 hierarchy slices have landed; acceptance and the release decision
remain.

**Goal:** Hold resident memory, VRAM, and main-thread frame cost roughly flat while the visible
distance grows from a 32-chunk radius to kilometres.

This page expands the [v0.0.9 roadmap entry](../roadmap.md) into concrete deliverables. The roadmap
remains the source of truth for milestone status and the Definition of Done. The analysis behind the
choices is in [GPU-driven meshing research](research/gpu-driven-meshing.md); the long-range LOD
representation is decided in [ADR-0014](../decisions/0014-seed-native-lod-hierarchy.md).

All numbers below are targets to verify, not guarantees. They are set against the reference machine
in [Engine research](research/README.md) (RTX 4060, Windows, Vulkan, 1280x720) and the minimum spec
in the GPU-driven spec (4 cores / 8 threads, 16 GB RAM, 8 GB VRAM, 1080p60). Draw and VRAM targets
assume the batched path is active; the fallback path keeps the v0.0.8 numbers.

## Definition of Done

- `render_distance_chunks = 32` holds 60 FPS with a working set at or below 350 MB and no more than
  40 MB of geometry VRAM.
- A 2 km view holds 60 FPS with a working set at or below 400 MB; an 8 km view holds 60 FPS at or
  below 500 MB. Both run from the spawn column of seed 42.
- Draw calls stay at or below 10 at distance 32 and at or below 20 at a 2 km view.
- Main-thread frame time stays at or below 4 ms at distance 32, with no frame above 33 ms once the
  first ring is ready.
- A block edit is visible within two frames, with the light field still computed on the CPU.
- With the hierarchy disabled, the v0.0.8 path behaves exactly as it does today and passes its
  existing tests.
- `ENGINE_HEADLESS=1` at distance 32 reports the same `chunks` and `generated_columns` as v0.0.8 for
  the same world, and a round-trip test shows the packed store decodes to the original block values.

## In scope

- In-memory block packing to four bits per cell, with `VCHK` unchanged on disk.
- Sparse light storage: the sky plane for every chunk, and the block-light plane only when a lamp is
  in range.
- Storage-buffer chunk info, quad pages in size-classed pools, vertex pulling, and one indirect draw
  per pass, with the current per-chunk path kept as the fallback.
- Horizon culling from column tops, plus fog and far plane coupling to the visible hierarchy.
- Seed-native hierarchy sections at levels 1-4: surface-only coarse generation, per-column sky
  light, parent retention, and CPU selection with hysteresis.
- Metrics for working set, geometry VRAM, visible sections, draw calls, and burst settle frames.
- Benchmarks for the mesher and the streaming/accepted-work paths, recorded in
  [Benchmark results](benchmarks.md).
- Documentation updates to [Architecture](architecture.md), [Culling](culling.md), and
  [Coordinates](coordinates.md), plus the changelog.
- [ADR-0015](../decisions/0015-quad-pool-and-indirect-draws.md) recording the quad-pool renderer and
  its fallback.

## Out of scope

- The compute mesher, GPU-resident voxel and light pools, and any readback-driven allocator.
- GPU culling passes, Hi-Z, and the voxel visibility graph; those stay proposed in
  [Culling](culling.md).
- Shadows, cascades, and any second geometry pass.
- Sub-voxel (4 cm) content.
- Binary greedy meshing and other worker-side mesher rewrites; they are analysed in
  [Meshing research](research/meshing.md) and deferred to a later milestone. The current greedy
  mesher stays the oracle.
- Save-format changes; `VCHK` v3 remains the format.
- Console backends.
- Gameplay, inventory, and survival systems.

## Technical shape

### Data and ownership

- `Block` stays a one-byte public value type. `World` stores blocks four bits per cell behind
  accessors, so the mesher, light, collision, raycast, and save code keep their current signatures.
- `LightField` keeps its `-1..=32` halo contract at the accessor. The sky plane is always stored; the
  block-light plane is present only when the 3x3x3 neighbourhood has a lamp, and the accessor returns
  zero when it is absent.
- `World` continues to own the authoritative L0 chunks and the modified set. Coarse sections are
  derived, disposable, and never saved.
- A new section type carries `(level, coord)`, extent `32 × 2^level` blocks, and the same `32³`
  sample budget as a chunk. Level 0 sections are chunks.
- The renderer owns one quad pool with size-classed pages, the chunk-info storage buffer, the
  indirect arguments, and the fallback per-chunk path.

### Algorithms and flow

- Cell packing is a representation change only: decode on read, encode on write, and keep the save
  path byte-per-cell.
- A light job seeds the block-light queue only from lamps. When the queue starts empty the block
  plane is dropped, so resident light falls from 39 KiB to 19 KiB per generated chunk.
- Coarse generation is a pure function of seed, level, and coordinate. It evaluates the height field
  over each sample footprint and fills columns; it does not sample three-dimensional caves or place
  trees.
- Coarse lighting is per-column sky light with zero block light on the first slice.
- LOD selection uses projected size with hysteresis, not fixed distance bands. A parent stays
  visible until all eight children are ready.
- Meshing writes quads into a page rather than a per-chunk vertex buffer. Pages come in 256-quad and
  1024-quad classes; a remesh takes one free page of the right class and frees the old page after the
  frames in flight that could still read it.
- Culling tests section AABBs against the frustum, skips face directions whose range faces away from
  the camera, and rejects sections entirely below the horizon bins built from column tops.
- The far plane and fog track the outer visible section, not the streaming radius.

### Rendering, storage, and generation

- The device requests storage buffers, `INDIRECT_FIRST_INSTANCE`, and
  `MULTI_DRAW_INDIRECT_COUNT`; the current per-chunk path remains selectable when a feature is
  missing. This drops the WebGL2-level limit request and is recorded in ADR-0015.
- The quad pool is a single buffer per size class with a page free list and an explicit
  frames-in-flight age per page. No suballocator and no readback trim in this milestone.
- Vertex pulling reads one quad per four indexed vertices through a shared `u16` pattern (the
  six-vertex non-indexed path remains for meshes above 16,383 quads); the vertex shader reads chunk
  and section info through `first_instance`.
- Water uses the same pool with a transparent flag and its own draw range, still unsorted.
- Pools are split under the 256 MB buffer cap by size class or slab index.
- Workers keep generation, light, and LOD0 meshing. The main thread allocates pages, writes staging
  data, records draws, and never blocks on meshing.

### Code shape

- `src/world.rs`: packed block storage; accessors unchanged.
- `src/light.rs`: sparse planes; the block-light plane is absent when empty.
- `src/mesh.rs`: quad emission and page sizing hints.
- `src/renderer.rs`, `src/pool.rs` (new), `src/shader.wgsl`: quad pool, indirect draws, vertex
  pulling, fallback.
- `src/section.rs` (new), `src/generation.rs`, `src/streaming.rs`: coarse sections, selection, and
  retention.
- `src/horizon.rs` (new), beside `src/frustum.rs`: horizon bins and tests.
- Tests live beside the code; the CPU mesher remains the oracle for quad output.

## Implementation slices

1. [x] **Measure the baseline.** Add the `bench_mesh_build` measurement beside `bench_hot_paths` for
   LOD0/1/2 and record working set, geometry bytes (a new total in the debug line), draws, and burst
   settle frames at distances 24 and 32. Raise `MAX_UPLOADS_PER_FRAME` in a measured side run and
   record the burst result. Result: baselines recorded; the upload cap measured 2 at 33 s settle,
   64 at 22 s, and 8 at 23 s on a retry, so 8 is the constant.
2. [x] **Pack blocks.** Four-bit in-memory block IDs, `VCHK` unchanged. Gate: the packed store
   round-trips every block type, all save, light, and mesh tests pass, and the headless working set
   drops by 16 KiB per chunk. Result: 294.5 MB at distance 24 and 517.1 MB at distance 32.
3. [x] **Sparse light.** Store the block-light plane only when a lamp is in range. Gate: identical
   light and mesh output, working set at or below 350 MB at distance 32. Result: 190.6 MB at
   distance 24 and 334.6 MB at distance 32, with meshing output unchanged.
4. [x] **Batch draws and page the quads.** Storage-buffer chunk info and one quad pool with
   per-range indirect arguments, consumed by the vertex shader (no per-chunk vertex or index
   buffers), one indirect draw per pass, current path as fallback. The record layout and limits are
   in [ADR-0015](../decisions/0015-quad-pool-and-indirect-draws.md). Gate: identical pixels, no
   frame-time regression, draws at or below 10, resident geometry at or below 40 MB at distance 32.
   Result: 2 draws, 37.6 MiB resident, 7.52 MiB visible, frame 1.84-1.87 ms; the stress scene renders
   correctly and the fallback remains. Post-audit hardening keeps the same output: LOD selection
   stays in sync with the queue, the args buffer covers both batches, the slot table covers the
   maximum render distance, and failed uploads retry a bounded number of times. Settled distance-32
   frame is now about 0.48 ms after the streaming and mesher/light work below; the GPU scene pass,
   measured with a timestamp scope, is 0.253 ms after indexed draws replaced six vertices per quad
   with four.
5. [x] **Horizon culling.** Column-top bins, conservative rejection, fog and far-plane coupling.
   Gate: sections removed with no visual holes at the render edge. Result: on by default; minimum
   column-top occluders, tree exclusion, and in-engine BMP captures on seeds 42/7 and a strafe view
   match the horizon-off images. It removes two-thirds of visible chunks and cuts the GPU scene from
   0.25 ms to 0.14 ms. `ENGINE_HORIZON_CULL=0` disables it.
6. [x] **Hierarchy slice 1.** Levels 1-2 sections, surface-only generation, per-column sky light,
   parent retention, projected-size selection. Gate: 2 km at 60 FPS and 400 MB. Result: projected
   selection with 72/62 px hysteresis, parent retention with hidden ready children, section edit
   invalidation, coarse water, and detail-16 L0. Settled west view: 0.466 ms frame, 0.235 ms GPU,
   3.58 M vertices, 2 draws, 30.94 MB allocated quads; L0 resident 85.9 MB. Coarse per-column light,
   missing far caves/trees, and the 250 ms target cadence are accepted for this slice.
7. [x] **Hierarchy slice 2.** Levels 3-4. Gate: 8 km at 60 FPS and 500 MB, draws at or below 20.
   Result: recursive projected refinement and parent retention for level-3/4 roots, 256 m
   (2-4 km) and 512 m (4-8 km) sections, and an 8M-quad (96 MB) hierarchy pool. The 8 km west view
   is 0.908 ms frame, 0.780 ms GPU, 1,908 visible nodes, 9.40 M vertices, 2 draws, 74.62 MB allocated
   quads, and 94.24 MB geometry reservation. L0 detail 16 is 85.9 MB resident.
8. [ ] **Acceptance.** Benchmarks, docs, changelog, ADR-0015, and the full acceptance run.
   Progress: the local benchmark, docs, changelog, fmt, clippy (including `--features tracy`), test,
   doc, typos, and mdbook runs pass; the release/PR decision is pending.

## Deliberate simplifications

| Simplification | Revisit when |
|---|---|
| Four-bit blocks, sixteen types | A mod or content set needs more; move to a palette then |
| Light stays on the CPU BFS | Edit latency measures as the remaining problem; start with sky light on compute |
| One active LOD per chunk is retained | Transition remeshes measure as visible or expensive |
| `quad.wgsl` duplicates the lit and water fragment code | The per-chunk fallback retires and the shared fragment module is worth the refactor |
| Fixed 3.2M-quad pool, no growth | The hierarchy or a larger render distance needs reallocation or a second pool |
| Fixed page size classes, no suballocator | Page waste exceeds 20% of pool memory |
| Horizon culling uses chunk-granularity column minima | A per-bin top measures enough extra culling to justify the build cost |
| Coarse sections are surface-only | Caves or trees are visible at the detail cutoff |
| No GPU traversal | The CPU hierarchy passes its gate and draw count is pressed further |

## Relationship to later milestones

- The page format and chunk-info buffer are the substrate a compute mesher would write into; nothing
  here precludes one, and the CPU mesher stays as the oracle.
- [ADR-0014](../decisions/0014-seed-native-lod-hierarchy.md) continues: levels 5+ and GPU traversal
  are later decisions.
- Shadows and sub-voxels build on the pool and section model, so they should be designed after this
  milestone's measurements, not against the current per-chunk buffers.
- Binary greedy meshing and other mesher rewrites are analysed in
  [Meshing research](research/meshing.md); they are a later CPU-perf slice, not part of these targets.
- Beyond the quad pool, chunk LOD with Hi-Z culling, a far heightfield ring, and 6-8 byte records are
  surveyed in [Geometry representation research](research/geometry-representation.md).
- A normative spec for this milestone follows once the baseline and quad-pool measurements in slices
  1 and 4 are in.
