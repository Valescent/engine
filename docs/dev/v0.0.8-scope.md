# v0.0.8 scope: Scale

**Status:** In progress - implementation and acceptance complete; release pending.

**Goal:** Make resident memory and per-frame cost scale with render distance, and raise the supported
render distance with a third LOD.

This page expands the [v0.0.8 roadmap entry](../roadmap.md) into concrete deliverables. The roadmap
remains the source of truth for milestone status and the Definition of Done. The normative numbers
are in the [v0.0.8 spec](../specs/v0.0.8.md).

## Definition of Done

- `world.render_distance_chunks` accepts `8..=32`; the default stays `12`.
- A world at `24` streams, lights, meshes, and holds 60 FPS on the reference machine.
- Resident light storage is at most half of v0.0.7 for the same chunk count.
- Loading a light job costs 27 chunk lookups, not a scan of the world.
- Streaming does not produce a main-thread frame above 33 ms once the first ring is ready.

## In scope

- Four-bit packed sky and block light fields, with the existing accessors and halo semantics.
- Direct `LightSnapshot` neighbour lookups.
- LOD2 as a 4x4x4 downsample for far chunks, a config range up to `32`, and the far plane and fog
  following it.
- Streaming pacing: a bounded generation queue, readiness bookkeeping that does not scan every
  loaded column each frame, and per-frame budget metrics.
- Benchmarks and memory measurements for the changed paths.
- Tests for packing, halo edges, LOD2 boundaries, selection hysteresis, and config ranges.

## Out of scope

- Gameplay, inventory, and survival systems.
- SVDAG and raymarching experiments; they remain deferred.
- GPU-side generation.
- Occlusion or horizon culling; LOD2 is the far-distance mechanism for this milestone.
- Chunk compression on disk; `VCHK` stays as it is.

## Technical shape

### Data and ownership

- `LightField` keeps two planes but stores one nibble per cell in `Box<[u8]>`; `sky` and `block`
  accessors keep the `-1..=32` halo contract.
- `LightSnapshot` holds only the 3x3x4 chunk footprint of the job, found by direct lookups.
  Missing chunks are air.
- `Lod` gains `Lod2`; `ChunkSnapshot` and the mesher gain a 4x4x4 downsample. LOD2 emits every
  boundary face, as LOD1 does.
- `Streaming` remembers which loaded columns are still unready instead of rescanning the loaded
  set, and generation requests respect a per-frame budget.

### Algorithms and flow

- Light propagation keeps its `u8` working grid; only the stored field and halo extraction are
  packed.
- LOD thresholds stay hysteretic: LOD0 inside 4 chunk units, LOD1 from 8, LOD2 from 16.
- The camera far plane remains `(render_distance + 2) * 32`; fog remains
  `0.7 * render_distance * 32` to `render_distance * 32`.
- Generation commits stay at two columns per frame; the queue cap bounds outstanding work.

### Rendering, storage, and generation

- The renderer keeps three LOD buffers per chunk; selection prefers the coarsest built LOD at or
  above the desired level until the exact one arrives.
- `VCHK` and `world/seed` are unchanged.
- Worker boundaries are unchanged: generation, light, and mesh jobs remain on the pool.

### Code shape

- `src/light.rs`: packed fields, direct snapshots.
- `src/mesh.rs`, `src/renderer.rs`, `src/mesher.rs`: LOD2.
- `src/streaming.rs`, `src/lib.rs`: pacing and readiness.
- `src/config.rs`: render distance range.

## Deliberate simplifications

| Simplification | Revisit when |
|---|---|
| Light propagation keeps a `u8` working grid | Packing the BFS proves faster in a benchmark. |
| LOD2 is a uniform 4x4x4 downsample | A distance-aware or meshlet scheme is measured. |
| No occlusion culling | LOD2 no longer holds the frame budget at the current distance. |
| Generation stays at two columns per frame | Pacing measurements show a better budget. |

## Relationship to later milestones

- A larger render distance depends on this milestone's memory and LOD work.
- Content milestones build on the seed, streaming, and save contracts, which this milestone leaves
  unchanged.
