# v0.0.3 scope: Chunks and Meshes

**Status:** Scoped; implementation not started.

**Goal:** Split the world into chunks, stop emitting hidden faces, and rebuild only the chunk meshes affected by an edit.

This page expands the [v0.0.3 roadmap entry](../roadmap.md#v003-chunks-and-meshes) into concrete deliverables. The roadmap remains the source of truth for milestone status and the Definition of Done.

## Definition of Done

- The world is made of multiple fixed-size chunks.
- Faces between two solid voxels are not emitted, including across chunk boundaries.
- An interior edit rebuilds one chunk.
- A boundary edit rebuilds the owning chunk and each neighbour whose boundary faces changed.
- Empty chunks release their GPU buffers.
- Frame time stays stable while flying through the scene.

## In scope

- `World` and `Chunk` storage with local coordinates.
- 32×32×32 chunks and Euclidean chunk-coordinate conversion.
- Six-neighbour face culling through the world.
- One GPU vertex buffer and one draw call per non-empty chunk.
- Dirty-chunk tracking for edits on chunk borders.
- A scene spanning four chunks, with `Space` toggling a boundary voxel.
- Rebuild timing, vertex-count, and dirty-chunk logging.
- CPU-only tests for storage, culling, meshing, and dirty chunks.

## Out of scope

- Greedy meshing, LOD, async meshing, and frustum culling (v0.0.5).
- Collision, raycasting, and block interaction (v0.0.4).
- Textures, block types, lighting, and persistence.

## Technical shape

### Chunk storage

- `CHUNK_SIZE = 32`.
- `World { chunks: HashMap<IVec3, Chunk> }`.
- `Chunk { voxels: HashSet<IVec3> }`, storing local coordinates from `0` to `31`.
- Missing chunks are treated as air.
- `World::insert`, `remove`, `toggle`, `is_solid`, and chunk iteration.
- Negative coordinates use `div_euclid`/`rem_euclid`; truncating division is incorrect.

### Dirty chunks

- Compute the owning chunk before mutating.
- An interior edit dirties one chunk.
- If the edited local coordinate is `0` or `31` on an axis, also dirty the neighbour on that side.
- Removing a chunk's last voxel deletes the chunk and dirties its neighbours.
- The caller rebuilds each unique dirty chunk once.

### Face culling

- For every voxel face, look up the neighbouring global coordinate through `World::is_solid`.
- Emit the face only when the neighbour is air.
- Culling must work across chunk boundaries.
- Sort local coordinates before meshing for deterministic output.

Expected vertex counts:

| Layout | Vertices |
|---|---:|
| One isolated voxel | 36 |
| Two adjacent voxels | 60 |
| Three voxels in a line | 84 |

Two adjacent voxels across a chunk boundary total 60, split 30/30 between the chunks.

### Rendering

- Replace the single vertex buffer with `BTreeMap<IVec3, GpuChunk>`.
- Each non-empty chunk owns one vertex buffer and vertex count.
- Upload or replace only the dirty chunks.
- Remove the GPU entry when a chunk mesh becomes empty.
- Draw every non-empty chunk with the existing pipeline, bind group, and camera uniform.

### Scene and controls

- Start with a 4×4 floor spanning `x/z = 30..=33`, crossing the `31/32` chunk boundary and therefore covering four chunks.
- Add a raised voxel at `(31, 1, 31)` and make it the `Space` toggle target.
- Retarget the camera to `(32, 0.5, 32)`; start it near `(37, 4.5, 38)`.
- The v0.0.2 fly camera remains the way to inspect the scene.
- Log dirty chunk count, total vertices, and rebuild time after an edit.

### Code shape

- Add `src/world.rs` for chunk storage and dirty tracking.
- Keep `Vertex` and chunk mesh generation in `src/voxel.rs`.
- Keep `src/renderer.rs` responsible for GPU buffers and drawing.
- Keep `src/lib.rs` responsible for input, camera, and wiring.

## Acceptance checklist

- [ ] The initial scene contains four non-empty chunks.
- [ ] Cross-chunk faces are culled correctly.
- [ ] Interior edits rebuild one chunk.
- [ ] Boundary edits rebuild the owning chunk and affected neighbours.
- [ ] Removing a chunk's last voxel removes its GPU buffer.
- [ ] Mesh output is deterministic.
- [ ] The camera flies through the scene at a stable frame rate.
- [ ] `Space` still changes the scene immediately.
- [ ] `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test --all-features`, `cargo doc --no-deps --all-features`, `typos`, and `mdbook build` pass.
- [ ] The README and roadmap are current and `CHANGELOG.md` has the user-visible entries.

## Deliberate simplifications

| Simplification | Revisit when |
|---|---|
| `HashSet<IVec3>` per chunk | Profiling shows storage or iteration is the bottleneck, or block types arrive. |
| Synchronous mesh rebuild on edit | Async meshing arrives in v0.0.5. |
| No greedy meshing, LOD, or frustum culling | v0.0.5. |
| One block colour | Textures and block types arrive in v0.0.4. |
| Small demo scene | World generation arrives in v0.0.7. |

## Relationship to later milestones

- v0.0.4 adds walking, collision, block interaction, persistence, and textures.
- v0.0.5 builds greedy meshing, LOD, frustum culling, and async meshing on these chunks.
