# v0.0.5 scope: Scale and Performance

**Status:** Complete.

**Goal:** Render a large view distance smoothly and remove frame hitches from chunk edits.

This page expands the [v0.0.5 roadmap entry](../roadmap.md#v005-scale-and-performance) into concrete deliverables. The roadmap remains the source of truth for milestone status and the Definition of Done.

See [v0.0.5 spec](../specs/v0.0.5.md) for the normative greedy, LOD, frustum, async, stress-scene, and metric contracts.

## Definition of Done

- A deterministic stress scene renders at the target draw distance with a stable frame rate.
- Greedy meshing measurably reduces vertices on flat terrain.
- Chunks outside the camera frustum are not drawn.
- Distant chunks use a coarser LOD without visible holes.
- Chunk remeshing runs on worker threads, and the main thread never blocks on meshing.
- Breaking blocks does not produce a visible frame hitch.

## In scope

- Greedy meshing with the v0.0.4 texture array.
- Two LOD levels with distance hysteresis.
- Frustum culling using per-chunk AABBs.
- Async chunk meshing on a worker pool.
- A deterministic stress scene for measurement.
- Per-frame metrics: visible chunks, vertices, draw calls, rebuild time, upload time, and frame time.
- CPU-only tests for greedy meshing, frustum tests, LOD selection, and async queue behaviour.

## Out of scope

- Lighting, fog, water, and transparency (v0.0.6).
- Procedural terrain and chunk streaming (v0.0.7).
- Async chunk generation.
- Changes to the save format or player controls.

## Technical shape

### Greedy meshing

- Sweep each chunk along each axis and direction.
- Build a 2D mask per slice keyed by block type, face direction, and texture layer.
- Merge adjacent equal entries into the largest possible quads.
- Emit one quad per merged run with UVs measured in block units.
- Use the texture array layer per quad; the shader repeats the tile across the quad.
- Keep the result deterministic by sweeping coordinates in a fixed order.
- Log vertex-count reduction for the stress scene.

### LOD

- LOD0: full-resolution chunk mesh.
- LOD1: one mesh built from a 2×2×2 downsample of the block grid.
- Choose LOD by chunk distance with hysteresis so boundaries do not flicker.
- Start with thresholds around 8 and 16 chunks and tune against the stress scene.
- Keep full block data for collision, editing, lighting, and saving; LOD only affects rendering.
- Invalidate and lazily rebuild LOD meshes when a block edit changes the chunk.

### Frustum culling

- Extract six frustum planes from the camera view-projection matrix each frame.
- Test each chunk's world-space AABB against the planes.
- Skip draw calls for chunks outside the frustum.
- Report visible versus total chunks in the metrics.

### Async meshing

- Run `cargo bench --bench pool_sim`, compare rayon and micropool on the same machine, and record the chosen pool in [ADR-0009](../decisions/0009-micropool-for-chunk-workers.md) before implementation. The decision selects micropool.
- Workers receive an immutable chunk snapshot, border block data, a target LOD, and a revision number.
- Workers return mesh data through a channel; they never touch the GPU or mutable world state.
- The main thread uploads at most a fixed number of chunk meshes per frame.
- Discard results whose revision is stale.
- Edits enqueue an urgent rebuild; background LOD work is lower priority.
- The main thread must never wait on a worker to finish a mesh.

### Stress scene and metrics

- Add a deterministic stress scene of at least 64 chunks with flat and uneven areas.
- Make the scene selectable for development without changing the saved world.
- Log frame time, visible chunks, total vertices, draw calls, rebuild time, and upload time at debug level.
- Use the stress scene as the acceptance measurement; do not run `pool_sim` in CI. Record local
  pool results in [Benchmark results](benchmarks.md).

### Code shape

- `src/mesh.rs` — greedy meshing and LOD mesh generation.
- `src/frustum.rs` — plane extraction and AABB tests.
- `src/mesher.rs` or a worker module — job queue, revisions, and result channel.
- `src/renderer.rs` — per-LOD buffers, frustum-filtered draws, and metrics.
- `src/lib.rs` — frame budget, upload scheduling, and integration.

## Deliberate simplifications

| Simplification | Revisit when |
|---|---|
| Two LOD levels | More levels are worth the transition and memory cost. |
| LOD1 by 2×2×2 downsampling | A better simplification metric is needed. |
| Frustum culling only; no occlusion culling | Occlusion testing shows a meaningful win. |
| Per-frame upload budget | Uploads become the bottleneck or streaming arrives. |
| No async chunk generation | v0.0.7 adds generated terrain. |
| Greedy meshing still uses per-chunk meshes | Larger merged meshes become worthwhile. |
