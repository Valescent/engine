# v0.0.10 scope: Basic mechanics

**Status:** In progress - checkpoint `0.0.10.1` is implemented: items, inventory, hold-to-break,
drops, pickup, placement, item rendering, and the player save. The `0.0.10.2` UI slice (egui HUD
and inventory screen) and the `0.0.10.3` crafting Phase 1 are also in; survival, audio, and
acceptance remain.

**Goal:** Turn the v1 terrain demo into a complete first playable loop: break, collect, craft,
place, survive, and save.

This page expands the [v0.0.10 roadmap entry](../roadmap.md) into concrete deliverables. The
roadmap remains the source of truth for milestone status and the Definition of Done. The wider
0.0.10-0.0.19 breakdown is in [the release plan](roadmap-0.0.10-0.0.19.md). The full crafting
design and its phased mapping are in [the crafting system](../design/crafting-system.md).

The acceptance run uses the v1 terrain demo (`TERRAIN_DEMO=1`). The legacy chunk world keeps the
v0.0.4 interaction path as a fallback; new gameplay is wired to the demo first.

## Definition of Done

- A new player can spawn, gather wood and stone, craft a tool, place blocks, and survive a fall.
- Breaking respects block hardness and tool tier; placement rejects occupied or unsupported cells.
- Inventory, hotbar, crafting, health, stamina, and respawn work without the debug overlay.
- The run survives quit and reopen with inventory, player state, dropped items, and edits intact.
- UI, audio, fixed-tick state, and the save-format bump are documented.

## Technical shape

### World target

`App` already selects between the v1 demo patch and the legacy `World`. The demo is the authority
for new interaction because it stores the blocks the player sees and stands on. The legacy path
keeps its instant break and place behaviour until the demo becomes the default.

### Items and inventory

- Item identity is the stable `namespace:name` string. Numeric ids are derived by sorting names at
  load, following the content-pack rule in ADR-0015. Save files store names, never numeric ids.
- A stack carries an item id, a count, and an optional durability. Stack size comes from the item
  definition.
- The inventory is 9 hotbar slots, 27 main slots, and one offhand slot. Operations are
  add, remove, split, merge, move, select, and take-one.
- Overflow goes to the first free slot, then to the ground as an entity.

### Tools and breaking

- Block hardness comes from the content pack (`BlockRecord::hardness`).
- Tool class and minimum tier are game tables keyed by block name. They move into the content pack
  when the authored pack lands.
- Break time is `hardness * class_multiplier / tier_speed`, with a minimum of one tick.
- A block whose minimum tier is above the tool's tier breaks without a drop.

### Entities

Dropped items use a minimal in-engine entity runtime (ADR-0020), not an ECS crate. An entity has a
stable `u64` id, an `ItemStack`, a position, a velocity, and an age. Physics runs on the fixed
tick; pickup queries use a spatial hash.

### Simulation clock

Break progress, entity physics, pickup, and despawn run at 60 Hz through an accumulator. Player
movement stays frame-driven in 0.0.10 because the camera has no render interpolation yet. This is
the one deliberate clock split; it is removed when interpolation lands.

### Persistence

The player save is a sidecar to the world save, not part of the terrain section store. The demo
writes `world/terrain-demo/player.dat`; the legacy world writes `world/player.dat`.

The file has a `VPLY` magic, a format version, the world seed, a CRC32, and a payload of player
position, view angles, inventory slots, selected slot, and item entities. Writes go to a temporary
file and rename; a corrupt file is moved aside with a `.bad` suffix and the run starts fresh.

The 0.0.10 save bump is the first player format. Later checkpoints add health, stamina, spawn
point, and recipes to the same versioned envelope.

### UI and audio

egui 0.37 renders through the existing wgpu device (ADR-0018). Input is routed to the UI first;
when a screen owns the pointer or keyboard, gameplay ignores it and the cursor is released.

kira 0.12 provides the mixer and positional buses (ADR-0019). Placeholder sounds are synthesised at
startup, so the repository carries no binary audio assets.
