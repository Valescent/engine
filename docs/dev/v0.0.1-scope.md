# v0.0.1 scope: The Foundation

**Status:** Implemented; release tag pending.

**Goal:** Render cubes from voxel data in a window, and let the voxel set be edited at runtime.

This page expands the [v0.0.1 roadmap entry](../roadmap.md#v001-the-foundation) into concrete deliverables. The roadmap remains the source of truth for milestone status and the Definition of Done.

## Definition of Done

- A window renders cubes from a `HashSet<IVec3>`.
- Adding or removing a coordinate visibly changes the scene.
- A static arrangement can be modified at runtime without restarting.

## In scope

- A `winit` window with a `wgpu` surface, depth buffer, and resize handling.
- A static perspective camera looking at the scene.
- `HashSet<IVec3>` voxel storage with add, remove, toggle, and contains operations.
- A mesh generated from the voxel set and uploaded as one vertex buffer.
- A single flat colour with per-face normal shading.
- `Space` toggling one voxel so runtime mutation is observable.
- CPU-only unit tests for storage and mesh generation.
- README controls, roadmap status, and changelog entry.

## Out of scope

- Chunking, face culling, greedy meshing, LOD, and async meshing (v0.0.2 and v0.0.4).
- Textures, texture atlases, and block types (v0.0.3).
- Lighting, fog, and transparency (v0.0.5).
- Camera controllers, collision, raycasting, and block interaction (v0.0.3).
- World generation and save/load (v0.0.6), and profiling (ADR-0006).
- A render graph, material system, plugin system, or engine façade.

## Technical shape

### Crates

Add `winit`, `wgpu`, `glam`, `bytemuck`, `pollster`, `thiserror`, `tracing`, and `tracing-subscriber`. `rayon` and `micropool` stay development dependencies for the v0.0.4 pool simulation.

### Modules

| Path | Contents |
|---|---|
| `src/main.rs` | Thin entry point that calls `engine::run()`. |
| `src/lib.rs` | `winit` application handler, static camera, and wiring. |
| `src/renderer.rs` | `wgpu` instance, surface, pipeline, depth buffer, and mesh buffers. |
| `src/voxel.rs` | `HashSet<IVec3>` storage, mesh generation, and tests. |
| `src/shader.wgsl` | Vertex and fragment shader. |

### Coordinates

- Right-handed, Y-up.
- A voxel at `(x, y, z)` occupies `[x, x + 1] × [y, y + 1] × [z, z + 1]`.
- Its centre is at `coordinate + 0.5`.

### Rendering

- One pipeline and one vertex format: position and normal.
- A cube contributes 36 non-indexed vertices, six per face.
- Voxel coordinates are sorted before meshing so output is deterministic.
- The whole set shares one vertex buffer; it is recreated when the set changes.
- Depth uses `Depth32Float`; the clear colour is a dark neutral.

### Camera

- Fixed position and look target; no camera input in this milestone.
- 60° vertical field of view, 0.1–100 m range.
- Aspect ratio updated on resize; zero-sized frames are skipped.

### Data flow

`Space` → toggle one coordinate in the set → rebuild the mesh → recreate the vertex buffer → redraw.

## Deliberate simplifications

| Simplification | Revisit when |
|---|---|
| `HashSet<IVec3>` used directly, without a newtype | Block types or storage invariants arrive. |
| One mesh for the whole world | Chunks arrive in v0.0.2. |
| Non-indexed 36 vertices per cube | Face culling and indexing arrive in v0.0.2. |
| Static camera | Player controls arrive in v0.0.3. |
| `Space` toggles one demo voxel | Block interaction arrives in v0.0.3. |
| One pipeline and one flat colour | Materials or transparency arrive. |
