# v0.0.6 spec: Atmosphere

**Status:** In progress - light, AO, and the light/AO vertex are implemented.

**Normative:** This page is the technical contract for v0.0.6. The
[roadmap](../roadmap.md) owns milestone status and the Definition of Done, and the
[v0.0.6 scope](../dev/v0.0.6-scope.md) owns deliverables and acceptance criteria. This page
owns light propagation, AO, the light/AO vertex fields, the day/night model, fog, water, and
the `VCHK` v2 extension. If the scope and this page disagree on a technical detail, this page is
authoritative and the scope is updated.

The keywords MUST, MUST NOT, SHOULD, and MAY are normative.

**Later milestone:** v0.0.7 adds Sand, an eleven-layer texture array, and `VCHK` v3, plus
generation/streaming and a configurable render distance; it supersedes the fixed `100 m` fog
range. See the [v0.0.7 spec](v0.0.7.md).

## 1. Scope

This spec covers:

- 4-bit sky and block light, sources, BFS, and edit invalidation.
- Per-corner light and AO in greedy quads.
- The 40-byte light/AO vertex and shader model.
- The ten-minute day/night cycle, keyframes, fog, and `T`.
- The `Lamp` and `Water` blocks, the transparent pass, and water animation.
- `VCHK` v2 persistence for the new block IDs.

Out of scope: shadow maps and real-time global illumination; volumetric fog, weather, and
clouds; reflections, refractions, swimming, and flow simulation; coloured light sources;
procedural terrain and streaming (v0.0.7).

## 2. Blocks, textures, and save format

`Block` gains two variants:

| ID | Block | Solid | Texture layer | Notes |
|---:|---|---:|---:|---|
| 6 | Lamp | Yes | 8 | Emits block light 14. |
| 7 | Water | No | 9 | Transparent, no light attenuation. |

- Block IDs `0..5` remain from v0.0.4.
- `Block::is_solid` MUST return `false` for Air and Water; true otherwise.
- `Block::layers` MUST return `Some` for Lamp and Water. Lamp uses layer 8 on every face;
  Water uses layer 9 on every face.
- The texture array grows to ten 16×16 RGBA8 layers. Layers `0..7` remain unchanged.
- Water is non-solid for collision, face culling, and raycasts.
- Lamp is solid and opaque.

### 2.1 `VCHK` v2

v0.0.6 writes format version `2`. The v0.0.4 header and record layout are unchanged except for
the version and valid block IDs.

- The loader MUST accept version `1` with block IDs `1..=5` and version `2` with block IDs
  `1..=7`.
- The writer MUST write version `2`.
- v1 files load without Lamp or Water.
- Light is still derived state and MUST NOT be saved.
- The v2 extension MUST be recorded in [ADR-0008](../decisions/0008-chunk-save-format.md) before
  implementation.

## 3. Light storage and propagation

See [ADR-0011](../decisions/0011-voxel-light-and-baked-ao.md) for the decision to use voxel
light and baked AO instead of shadow maps.

Each chunk stores:

```rust
pub(crate) struct Chunk {
    pub(crate) blocks: HashMap<IVec3, Block>,
    pub(crate) sky_light: Box<[u8]>,
    pub(crate) block_light: Box<[u8]>,
}
```

- Each light array has exactly `32 * 32 * 32` bytes, indexed by local coordinates in
  `0..=31`.
- Every value MUST be in `0..=15`.
- Light is derived state. It is recomputed after loading and never written to `VCHK`.
- Solid cells store `0` sky light. Lamp cells store block light `14`. Air and Water cells may
  store any value `0..=15`.

### 3.1 Sources and BFS

Sky light:

- A non-solid cell has `sky_light = 15` when no solid block exists above it in the loaded
  vertical column. Missing chunks above count as air.
- Every source cell is queued. BFS spreads through six-connected non-solid neighbours with
  `next = current - 1`, keeping the maximum.
- Water does not attenuate light; a step through Water keeps the same value.
- Solid blocks stop propagation.

Block light:

- Every Lamp cell has `block_light = 14` and is queued.
- BFS spreads through six-connected non-solid neighbours with `next = current - 1`, keeping the
  maximum.
- Water does not attenuate; solid blocks stop propagation.

A light job MUST compute light for the target chunk and one cell of border on every side. The
border is used for meshing. The center 32³ arrays are stored on the chunk.

### 3.2 Light snapshots and jobs

Lighting runs on the v0.0.5 worker pipeline. A light job receives an immutable snapshot with:

- The target chunk's full-resolution blocks.
- The 3×3×3 loaded chunk neighbourhood for local propagation.
- Every loaded chunk above the target in the same 3×3 horizontal footprint, so sky exposure is
  exact.

Missing chunks are air.

```rust
pub(crate) struct LightJob {
    pub(crate) chunk: ChunkCoord,
    pub(crate) revision: u64,
    pub(crate) snapshot: LightSnapshot,
}

pub(crate) struct LightResult {
    pub(crate) chunk: ChunkCoord,
    pub(crate) revision: u64,
    pub(crate) light: LightField,
}
```

`LightField` holds sky and block light for the center chunk plus one border cell. It is
`34³` padded, indexed from local `-1..=32`, or an equivalent representation.

- Light jobs use the v0.0.5 revision, priority, queue, and stale-result rules.
- Edit lighting is urgent; background work is lower priority.
- The main thread MUST NOT wait for a light job.
- Mesh jobs use the accepted `LightField`; stale light results are discarded.
- The v0.0.5 two-mesh upload budget still applies to mesh uploads. Light fields are CPU state.

### 3.3 Edit invalidation

Because sky and block light propagate at most 15 blocks, an edit light-dirties:

- The owning chunk.
- Every loaded chunk whose chunk coordinate differs by at most one on each axis: at most a
  3×3×3 neighbourhood.
- If the edit changes solidity in a column, every loaded chunk below that cell in the same
  vertical column, because sky exposure can change all the way down.

Every light-dirty chunk is remeshed after its new light is accepted. The v0.0.4 face-culling
dirty set is a subset; the light-dirty set may be larger. The v0.0.5 async pipeline and revision
checks apply.

## 4. Light and AO in meshes

### 4.1 Vertex layout

`Vertex` extends the v0.0.5 36-byte layout with one packed field:

```rust
#[repr(C)]
#[derive(Clone, Copy, Debug, PartialEq, Pod, Zeroable)]
pub(crate) struct Vertex {
    pub(crate) position: [f32; 3],
    pub(crate) normal: [f32; 3],
    pub(crate) uv: [f32; 2],
    pub(crate) layer: u32,
    pub(crate) light_ao: u32,
}
```

`light_ao` packing:

| Bits | Field |
|---:|---|
| 0–3 | sky light `0..=15` |
| 4–7 | block light `0..=15` |
| 8–9 | AO level `0..=3` |
| 10–31 | zero |

The vertex is 40 bytes. The shader MUST unpack the three fields.

### 4.2 Corner sampling

For an opaque face, let `outside` be the non-solid cell adjacent to the face. For a face
corner with u/v signs `su` and `sv`, inspect these four cells in the outside layer:

- `outside`
- `outside + su * u_axis`
- `outside + sv * v_axis`
- `outside + su * u_axis + sv * v_axis`

For each corner:

- Sky light and block light are the component-wise maximum over the non-solid cells in that
  set.
- `side_a` and `side_b` are whether the two edge neighbours are solid.
- `diagonal` is whether the diagonal neighbour is solid.
- If `side_a && side_b`, AO is `0`. Otherwise AO is
  `3 - (side_a as u8 + side_b as u8 + diagonal as u8)`.
- AO is four levels: `0` fully occluded through `3` open.

For a Water face:

- The four corner light values are the Water cell's sky and block light, uniform across the
  face.
- AO uses the same solid checks around the face corner.
- Water faces do not sample light from the air outside the surface.

LOD1 uses the topmost solid source block of each downsampled cell as its representative for
texture, light, and AO. It applies the same full-resolution corner rule to that representative.
Water is rendered at full resolution only; LOD1 does not create a water mesh in v0.0.6. See
[ADR-0010](../decisions/0010-two-level-lod-for-chunks.md).

### 4.3 Greedy merge key

The v0.0.5 greedy algorithm and order remain. The mask key is extended:

```text
(block, face, texture_layer, [sky/block, ao] at corner 0..3)
```

A mask cell can merge only with cells whose full key matches, including all four corner light
and AO values. Quads therefore split at light and AO discontinuities. The emitted quad's four
vertices use the key's corner values.

This applies to LOD0 and LOD1. LOD1 positions and UVs are still scaled by two, and its boundary
faces are still always emitted.

## 5. Shader, day/night, and fog

### 5.1 Time

- `time_of_day` is a uniform in `[0, 1)`.
- A full cycle is 600 seconds.
- Start at `0.25`; advance by `delta_seconds / 600.0` each frame, wrapping.
- `T` adds `1.0 / 24.0` (one hour), wrapping.
- The README MUST document the 600-second cycle and the `T` debug key.

### 5.2 Sun, moon, and keyframes

Sun direction: `(cos(2π * time), sin(2π * time), 0)`. Moon direction is the negation.
`time = 0.25` is noon; `0.75` is midnight.

| Time | Phase | Sky colour | Ambient colour | Sun colour |
|---:|---|---:|---:|---:|
| 0.00 | dawn | `[0.55, 0.35, 0.30]` | `[0.32, 0.28, 0.30]` | `[1.00, 0.65, 0.45]` |
| 0.25 | day | `[0.45, 0.65, 0.90]` | `[0.65, 0.70, 0.75]` | `[1.00, 0.95, 0.85]` |
| 0.50 | dusk | `[0.50, 0.30, 0.25]` | `[0.28, 0.25, 0.27]` | `[1.00, 0.55, 0.35]` |
| 0.75 | night | `[0.02, 0.03, 0.08]` | `[0.06, 0.08, 0.14]` | `[0.50, 0.60, 0.80]` |

- Colours are linear RGB.
- Interpolate linearly between adjacent keyframes and wrap from night back to dawn.
- Sun strength is `max(sun_direction.y, 0)`; moon strength is `max(-sun_direction.y, 0)`.
- Moon colour is `[0.50, 0.60, 0.80]`.

### 5.3 Lighting model

For a fragment:

```text
sky = sky_light / 15
block = block_light / 15
ao = 0.55 + 0.15 * ao_level
ambient = ambient_colour * sky
sun = sun_colour * max(dot(normal, sun_dir), 0) * max(sun_dir.y, 0) * sky
moon = moon_colour * max(dot(normal, -sun_dir), 0) * max(-sun_dir.y, 0) * sky
lamp = [1.00, 0.75, 0.45] * block
lit = texture.rgb * ao * (ambient + sun + moon + lamp)
```

The result MUST be clamped to `[0, 1]`. The shader retains the v0.0.4 face-shading path as an
unlit debug fallback; a uniform flag selects it.

### 5.4 Fog

- Fog is linear from `70%` to `100%` of the camera far plane.
- Distance is Euclidean camera-to-fragment distance.
- `fog_factor = clamp((distance - 0.7 * far) / (0.3 * far), 0, 1)`.
- The fog colour is the current interpolated sky colour.
- The final colour is `mix(lit, sky_colour, fog_factor)`.
- The far plane remains `100 m`; fog start is `70 m` and end is `100 m`.

## 6. Water

- Water is a non-solid block with block ID `7` and texture layer `9`.
- Water does not attenuate sky or block light.
- The opaque mesh excludes Water cells. Opaque solid faces adjacent to Water are emitted
  because Water is not solid.
- Each chunk builds a separate transparent water mesh. It uses the v0.0.5 greedy mesher with
  Water cells, layer 9, and light/AO.
- `GpuChunk` gains `water: Option<GpuMesh>`.
- `upload_water_chunk(chunk, mesh)` creates or replaces the buffer; an empty mesh removes it.
- Water mesh uploads share the v0.0.5 two-mesh-per-frame budget.
- A Water face is emitted only when the neighbour is Air. Water-water and Water-solid faces
  are culled.
- Water vertices use the Water cell's sky/block light and the corner AO rule.
- Water is rendered after all opaque meshes with depth testing on and depth writes off
  (`LessEqual`).
- Water draws use ascending `ChunkCoord` order for determinism.
- Blending is `SrcAlpha` / `OneMinusSrcAlpha` with alpha `0.65`.
- Water faces are not sorted. The README and this spec MUST document the ordering limitation.
- Water normals animate with time:
  `phase = 40π * time_of_day`,
  `wave = (sin(phase + world.x * 0.7 + world.z * 0.5), 0,
  cos(phase + world.x * 0.6 - world.z * 0.4))`,
  `normal = normalize(normal + 0.15 * wave)`.
- Water does not affect collision, movement, or swimming.
- Water meshes are full-resolution in v0.0.6; they are not LOD1.

## 7. Required tests

CPU-only tests MUST cover:

- Sky light in open columns, horizontal falloff, and dark caves.
- Block light from Lamp with distance falloff.
- Water passing light without attenuation.
- Cross-chunk light propagation and border light.
- The 3×3×3 light-dirty set plus column-below invalidation on solidity changes.
- Light is not written to `VCHK`; loading recomputes it.
- AO values at open corners, one-sided occluders, and two-sided corners.
- Per-corner light/AO sampling and greedy splitting at light/AO changes.
- LOD1 representative light/AO, and no LOD1 water mesh.
- The 40-byte vertex packing and shader unpacking.
- Day/night keyframes, interpolation, `T`, and wrap behaviour.
- Fog factor at near, start, end, and beyond the far plane.
- Water classification, face culling, greedy output, alpha, and depth state.
- `VCHK` v2 round-trip for Lamp and Water, and v1 file loading.
- Light and mesh jobs reject stale revisions and never block the main thread.
