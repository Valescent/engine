# v0.0.4 spec: Playable

**Status:** Implemented; awaiting the v0.0.4 release.

**Normative:** This page is the technical contract for v0.0.4. The
[roadmap](../roadmap.md) owns milestone status and the Definition of Done, and the
[v0.0.4 scope](../dev/v0.0.4-scope.md) owns deliverables and acceptance criteria. This page
owns block storage, player physics, raycasting, interaction, texture layers, and the `VCHK` v1
format. If the scope and this page disagree on a technical detail, this page is authoritative
and the scope is updated.

The keywords MUST, MUST NOT, SHOULD, and MAY are normative.

**Later milestones:** v0.0.6 extends the texture array to ten layers, `Vertex` to 40 bytes,
and `VCHK` to v2 for Lamp and Water. v0.0.7 adds Sand, an eleven-layer array, and `VCHK` v3.
See the [v0.0.6](v0.0.6.md) and [v0.0.7](v0.0.7.md) specs.

## 1. Scope

This spec covers:

- The `Block` enum and block-aware chunk storage.
- The walking player, gravity, jumping, and swept AABB collision.
- DDA raycasting, break and place interaction, and the wireframe highlight.
- Texture-array layers, the textured vertex layout, and hotbar selection.
- `VCHK` v1 chunk persistence and startup/shutdown save/load.
- The first-run demo world and its required block mix.

Out of scope: streaming and generated terrain (v0.0.7); lighting, fog, water, and transparency
(v0.0.6); LOD, greedy meshing, and async meshing (v0.0.5); swimming, inventory UI, crafting,
and multiplayer.

## 2. Block model and storage

```rust
#[repr(u8)]
#[derive(Clone, Copy, Debug, Eq, Hash, PartialEq)]
pub(crate) enum Block {
    Air = 0,
    Stone = 1,
    Dirt = 2,
    Grass = 3,
    Wood = 4,
    Leaves = 5,
}

pub(crate) struct FaceLayers {
    pub(crate) top: u32,
    pub(crate) side: u32,
    pub(crate) bottom: u32,
}

impl Block {
    pub(crate) fn is_solid(self) -> bool;
    pub(crate) fn layers(self) -> Option<FaceLayers>;
}
```

- `Block` IDs above are the on-disk IDs and MUST remain stable for format version 1.
- `is_solid` MUST return `false` only for `Air`.
- `layers` MUST return `None` for `Air` and `Some` for every solid block.
- The face layer mapping is defined in section 5.

Chunks must replace the v0.0.3 `HashSet<IVec3>` with a sparse block map:

```rust
pub(crate) struct Chunk {
    pub(crate) blocks: HashMap<IVec3, Block>,
}

impl World {
    pub(crate) fn block(&self, world: IVec3) -> Block;
    pub(crate) fn set_block(&mut self, world: IVec3, block: Block) -> DirtyChunks;
    pub(crate) fn is_solid(&self, world: IVec3) -> bool;
}
```

Invariants:

- `World::chunks` MUST NOT contain an empty chunk.
- `Chunk::blocks` MUST NOT contain an `Air` value.
- Every stored local coordinate MUST be in `0..=31` on every axis.
- `block(world)` MUST return `Air` when the owning chunk or local coordinate is missing.
- `is_solid(world)` MUST equal `block(world).is_solid()`.
- Stored block changes MUST preserve the v0.0.3 rule that absent chunks are air.

### 2.1 `set_block` dirty rules

`set_block` replaces `insert`, `remove`, and `toggle` from v0.0.3.

- If `block(world)` already equals the requested block, return an empty dirty set.
- Setting `Air` on `Air` is a no-op.
- If the request changes solidity on an axis where the local coordinate is `0` or `31`, the
  touched neighbour MUST be added to the dirty set.
- If solidity does not change, only the owning chunk is dirty. Changing one solid block type
  to another changes the face texture but not neighbour culling.
- If setting `Air` removes the last block, the chunk MUST be deleted from `World::chunks`. The
  deleted chunk and each touched neighbour MUST be in the dirty set.
- If setting a solid block creates a missing chunk, the owning chunk and each touched neighbour
  MUST be in the dirty set.
- Dirty sets MUST use the ordered, duplicate-free `DirtyChunks` from the v0.0.3 spec.
- A dirty set MAY contain a chunk that is not currently in `World`; missing chunks produce an
  empty mesh and no GPU entry.

The 32×32×32 chunk size and `ChunkCoord` ordering remain from v0.0.3.

## 3. Player and collision

```rust
pub(crate) const PLAYER_WIDTH: f32 = 0.6;
pub(crate) const PLAYER_HEIGHT: f32 = 1.8;
pub(crate) const EYE_HEIGHT: f32 = 1.62;
pub(crate) const WALK_SPEED: f32 = 4.5;
pub(crate) const GRAVITY: f32 = 24.0;
pub(crate) const JUMP_VELOCITY: f32 = 8.0;

pub(crate) struct Player {
    pub(crate) position: Vec3,
    pub(crate) velocity: Vec3,
    pub(crate) on_ground: bool,
}

pub(crate) struct PlayerInput {
    pub(crate) forward: f32,
    pub(crate) right: f32,
    pub(crate) jump: bool,
    pub(crate) yaw: f32,
}

pub(crate) struct Aabb {
    pub(crate) min: Vec3,
    pub(crate) max: Vec3,
}

impl Player {
    pub(crate) fn new(position: Vec3) -> Self;
    pub(crate) fn eye_position(&self) -> Vec3;
    pub(crate) fn aabb(&self) -> Aabb;
    pub(crate) fn update(&mut self, world: &World, input: PlayerInput, delta: f32);
}
```

`Player::position` is the centre of the feet, not the eye.

- The AABB MUST have `min = position + (-0.3, 0, -0.3)` and
  `max = position + (0.3, 1.8, 0.3)`.
- The eye MUST be `position + Vec3::Y * 1.62`.
- The camera's world position MUST be the eye position.
- The camera's yaw and pitch remain the v0.0.2 camera's. Mouse look is unchanged.
- WASD MUST move horizontally using yaw only; pitch MUST NOT affect walk direction.
- The forward and right vectors are `(sin yaw, 0, -cos yaw)` and
  `(cos yaw, 0, sin yaw)`.
- Input axes MUST be normalized before applying `WALK_SPEED`.
- A non-positive `delta` MUST be a no-op.
- Horizontal velocity MUST be set directly from input each frame. There is no acceleration,
  friction, sprint, or crouch.
- Air control MUST match ground control.
- Gravity MUST subtract `GRAVITY * delta` from vertical velocity each frame.
- A jump MUST set vertical velocity to `JUMP_VELOCITY` only when `on_ground` is true at the
  start of the frame. Jump input is edge-triggered; key repeat is ignored.
- The update order MUST be: set horizontal velocity, apply jump, subtract gravity, then move
  Y, X, Z.
- There is no coyote time or jump buffering.

### 3.1 Axis order and collision response

Movement resolves in this order: Y, then X, then Z.

- Y is resolved first so a downward collision establishes `on_ground` for the frame.
- Each axis uses a swept AABB against the solid voxel AABBs in the world.
- On contact, the player MUST be clamped to the contact plane, and that velocity component
  MUST be set to zero.
- A downward Y collision MUST set `on_ground = true`. Any other Y result MUST set
  `on_ground = false`.
- X and Z collisions MUST zero only their own velocity component.
- No step-up, slopes, swimming, or water collision is implemented.
- Swept collision MUST prevent tunnelling at `WALK_SPEED`, `GRAVITY`, `JUMP_VELOCITY`, and the
  existing 100 ms frame-delta clamp.
- A zero-length axis movement MUST be a no-op.

### 3.2 Spawn

- A spawn point MUST place the player AABB entirely outside solid blocks.
- The demo scene MUST designate a spawn column with a solid surface; the player starts above
  the highest solid block in that column and falls onto it.
- If the loaded world is empty, the default spawn point is used and no ground is guaranteed;
  the player may fall. Void handling is out of scope.

## 4. Raycast, interaction, and highlight

```rust
pub(crate) struct RaycastHit {
    pub(crate) block: IVec3,
    pub(crate) normal: IVec3,
}

pub(crate) fn raycast(
    world: &World,
    origin: Vec3,
    direction: Vec3,
    max_distance: f32,
) -> Option<RaycastHit>;
```

- The interaction ray MUST start at the eye and follow the camera's forward direction.
- `max_distance` for interaction is `6.0` metres.
- `raycast` MUST use DDA grid traversal and return the first solid voxel entered.
- The start cell is `origin.floor()` as an integer coordinate. If the start cell is solid,
  return `None`.
- Boundary ties MUST resolve in X, then Y, then Z order.
- `normal` MUST point out of the hit block toward the ray origin, on the face that was entered.
- A non-zero direction MUST be normalized before traversal. A zero-length direction MUST
  return `None`.
- A hit farther than `max_distance` MUST return `None`.

Interaction rules:

- Block interaction requires cursor capture. The first left click after release captures only;
  it does not break or place.
- Capture is acquired by left click only. Right click is not a capture button.
- Once captured, left click breaks the targeted block by setting it to `Air`.
- Once captured, right click places the selected solid block at `hit.block + hit.normal`.
- Placement MUST be rejected when the destination is occupied or when the new block's unit
  cube intersects the player AABB.
- Breaking and placing MUST call `set_block` and rebuild only the returned dirty chunks using
  the v0.0.3 path.
- Each click performs one action. Hold-to-repeat is not implemented.
- No action occurs when the ray misses.
- `Space` no longer toggles the demo voxel; it is the jump input.

Highlight:

- The highlight MUST be a wireframe cube drawn as a line list.
- It MUST use 24 vertices for the 12 cube edges and a `HighlightVertex { position: [f32; 3] }`
  layout.
- It MUST follow the current raycast hit and disappear when there is no hit within range.
- It MUST be depth-tested and drawn as a separate pass or draw from chunk meshes.
- The exact colour and the small expansion used to avoid z-fighting are implementation-defined.

## 5. Textures, vertices, and hotbar

```rust
pub(crate) const TEXTURE_LAYERS: u32 = 8;
pub(crate) const TEXTURE_SIZE: u32 = 16;

#[repr(C)]
#[derive(Clone, Copy, Debug, PartialEq, Pod, Zeroable)]
pub(crate) struct Vertex {
    pub(crate) position: [f32; 3],
    pub(crate) normal: [f32; 3],
    pub(crate) uv: [f32; 2],
    pub(crate) layer: u32,
}
```

The renderer MUST use a `texture_2d_array` with eight 16×16 RGBA8 layers:

| Layer | Tile |
|---:|---|
| 0 | stone |
| 1 | dirt |
| 2 | grass top |
| 3 | grass side |
| 4 | grass bottom |
| 5 | wood top and bottom |
| 6 | wood side |
| 7 | leaves |

The block-face mapping is normative:

| Block | Top | Side | Bottom |
|---|---:|---:|---:|
| Stone | 0 | 0 | 0 |
| Dirt | 1 | 1 | 1 |
| Grass | 2 | 3 | 4 |
| Wood | 5 | 6 | 5 |
| Leaves | 7 | 7 | 7 |
| Air | — | — | — |

- Placeholder tiles MUST be generated procedurally and deterministically. Exact pixels and
  colours are not normative.
- Texture filtering MUST be nearest and mipmaps MUST NOT be generated.
- The vertex layout is 36 bytes and replaces the 24-byte v0.0.3 vertex.
- The v0.0.3 face order, corner offsets, winding, chunk-local positions, and per-chunk origin
  remain normative.
- The four corners of every face receive UVs `(0,0)`, `(0,1)`, `(1,1)`, `(1,0)` in corner
  order.
- The shader MUST sample the texture array with the per-vertex layer.
- The texture array MUST NOT be replaced with a flat atlas. See
  [ADR-0007](../decisions/0007-texture-array-for-block-textures.md).

Hotbar:

- Number keys set the selected block: `1` Stone, `2` Dirt, `3` Grass, `4` Wood, `5` Leaves.
- The default selection is Stone.
- `Air` MUST NOT be selectable.
- There is no visible hotbar UI and no inventory UI; selection is internal state only.
- Number keys MAY change the selection while focused, whether or not the cursor is captured.

## 6. Persistence: `VCHK` v1

The save directory is `world/chunks/`. Each non-empty chunk is one file:

```text
chunk_{x}_{y}_{z}.vchk
```

Chunk coordinates are decimal `i32` values; negative values keep their leading `-`.

```rust
pub(crate) enum SaveError {
    Io(std::io::Error),
    InvalidFileName(String),
    InvalidMagic,
    UnsupportedVersion(u16),
    InvalidChunkCoordinate(IVec3),
    InvalidBlockCount(u32),
    InvalidLocalCoordinate(IVec3),
    InvalidBlockId(u8),
    DuplicateRecord(IVec3),
    DuplicateChunk(ChunkCoord),
    ChunkMismatch { file: ChunkCoord, header: ChunkCoord },
    Truncated,
    TrailingBytes,
}

impl World {
    pub(crate) fn load_chunks(directory: &Path) -> Result<Self, SaveError>;
    pub(crate) fn save_chunks(&self, directory: &Path) -> Result<(), SaveError>;
}
```

`SaveError` is the typed persistence error; `RunError` wraps it. The loader MUST reject
chunk coordinates whose minimum corner `chunk * 32` does not fit in `i32`.

### 6.1 File layout

All integers are little-endian.

| Offset | Size | Field |
|---:|---:|---|
| 0 | 4 | magic, the bytes `VCHK` |
| 4 | 2 | format version, `1` |
| 6 | 4 | chunk X |
| 10 | 4 | chunk Y |
| 14 | 4 | chunk Z |
| 18 | 4 | block count |
| 22 | `4 × block_count` | records |

Each record is four bytes:

| Offset | Size | Field |
|---:|---:|---|
| 0 | 1 | local X, `0..=31` |
| 1 | 1 | local Y, `0..=31` |
| 2 | 1 | local Z, `0..=31` |
| 3 | 1 | block ID, `1..=5` |

- `block_count` MUST be between `1` and `32768`.
- Records MUST NOT contain `Air` (`0`) or an unknown block ID.
- Records MUST be unique and sorted ascending by `(x, y, z)` when saved.
- The loader MAY accept unsorted records but MUST reject duplicates.
- The file MUST end immediately after the last record. Trailing bytes are invalid.
- No checksums and no compression are part of v1.

### 6.2 Loading

- `world/chunks/` missing as a whole: return an empty world to the loader. The application then
  seeds the demo scene.
- `world/chunks/` exists but is empty: load an empty world and do NOT seed the demo scene.
- Only regular files ending in `.vchk` are loaded. Other files are ignored.
- A filename that does not match `chunk_{x}_{y}_{z}.vchk` is a typed error.
- The filename chunk coordinates MUST match the header chunk coordinates.
- Two files with the same header chunk coordinate are a typed error.
- A malformed file, unknown version, bad magic, invalid record, truncated record, trailing byte,
  duplicate record, or I/O failure MUST abort startup with a typed error naming the file and
  reason. The world MUST NOT be partially loaded.
- The save format MUST be recorded in [ADR-0008](../decisions/0008-chunk-save-format.md) before
  persistence is implemented.

### 6.3 Saving

- Saving MUST create `world/` and `world/chunks/` when missing.
- Saving MUST write every non-empty chunk as one file.
- Saving MUST remove `.vchk` files whose chunk is no longer non-empty, so deleted chunks do not
  reload.
- Chunks MUST be written in ascending `ChunkCoord` order; records are sorted as in section 6.1.
- Saving MUST happen on clean exit and on `Ctrl+S`.
- Save errors MUST be logged at error level and returned as typed errors. They MUST NOT panic.
- `Ctrl+S` save errors do not terminate the running engine.
- Exit save errors are logged before the process exits.
- The save directory MUST be ignored by Git.

The existing `RunError` MUST gain a world/save variant so startup load errors surface through
the normal startup error path.

## 7. Scene, controls, and logging

The first run with no `world/chunks/` seeds a demo world. The demo world MUST contain:

- Grass immediately above Dirt in at least one column.
- At least one Stone block.
- At least one Wood block.
- A spawn point above a solid surface with a clear player AABB.

The exact demo layout is presentation and is not a normative test vector. An existing empty
`world/chunks/` directory stays empty and is not reseeded.

Controls:

| Input | Action |
|---|---|
| `W` / `S` | Walk forward / back using yaw |
| `A` / `D` | Walk left / right using yaw |
| Mouse | Look while captured and focused |
| Left click | Capture first, then break |
| Right click | Place selected block |
| `Space` | Jump |
| `1`–`5` | Select Stone, Dirt, Grass, Wood, or Leaves |
| `Ctrl+S` | Save all non-empty chunks |
| `V` | Toggle vsync |
| `F3` | Toggle the FPS/frame-time overlay |
| `Escape` | Release the cursor |

- The v0.0.2 capture and focus rules remain: mouse look requires capture and focus, losing focus
  clears held keys and releases capture, and `Escape` does not pause the engine.
- The v0.0.2 fly-camera movement is replaced by walking; mouse look remains.
- There is no hotbar UI, inventory UI, pause menu, sprint, crouch, hotbar wheel, or gamepad
  input.

The v0.0.3 debug logs for dirty chunk count, total vertices, and rebuild time remain required
after edits.

## 8. Required tests

CPU-only tests MUST cover:

- `Block::is_solid`, IDs, and face-layer mapping.
- No `Air` values stored and no empty chunks.
- `set_block` for solid-to-solid, solid-to-air, air-to-solid, same-block, interior, border,
  corner, and last-block removal.
- Dirty sets from `set_block`, including neighbours only when solidity changes.
- Player AABB and eye position.
- Gravity, jump, ground detection, and Y-X-Z collision order.
- No tunnelling at the configured speed, gravity, jump velocity, and 100 ms delta.
- No step-up and no slope handling.
- DDA hits, miss, range limit, tie-break order, and face normals.
- Placement rejection for occupied cells and player intersection.
- Break/place rebuilds only the affected chunks.
- Texture layer table, UV order, and the 36-byte vertex layout.
- `VCHK` round-trip, negative chunk coordinates, local `0` and `31`, stale-file removal,
  missing versus empty directory, and every malformed-file error path.
- Missing and malformed save handling does not panic.

Manual GPU acceptance remains in the [v0.0.4 scope](../dev/v0.0.4-scope.md#acceptance-checklist)
and [Testing](../dev/testing.md). The scope's acceptance checklist and the roadmap's Definition
of Done remain authoritative for milestone completion.
