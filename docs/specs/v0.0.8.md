# v0.0.8: Scale

**Status:** In progress - implementation and acceptance complete; release pending.

This page is the normative contract for the v0.0.8 milestone. The [roadmap](../roadmap.md) owns
milestone status and the Definition of Done, and the
[v0.0.8 scope](../dev/v0.0.8-scope.md) owns deliverables and acceptance criteria. This page
owns the render-distance limits, light storage, LOD rules, and streaming budgets. If the scope and
this page disagree on a technical detail, this page is authoritative and the scope is updated.

The keywords MUST, MUST NOT, SHOULD, and MAY are normative.

## 1. Scope

The milestone changes resident memory, per-frame scan cost, and the supported render distance. It
does not add gameplay, save-format changes, GPU generation, or new renderer paths.

## 2. Render distance and camera

- `world.render_distance_chunks` MUST accept `8..=32`. The default stays `12`.
- The streaming ring, unload margin, and candidate order remain as in v0.0.7.
- The camera far plane MUST be `(render_distance + 2) * 32` metres.
- Fog MUST run from `0.7 * render_distance * 32` to `render_distance * 32` metres.
- The config file keeps rejecting unknown keys, malformed values, duplicates, and out-of-range
  values with typed errors.

## 3. Light storage

- `LightField` MUST store sky and block light as two packed planes, one nibble per cell, in
  `-1..=32` on each axis.
- Values MUST stay in `0..=15`; `MAX_LIGHT` is `15`.
- `sky(local)` and `block(local)` MUST keep returning the same values as v0.0.7 for every cell in
  the halo.
- Packing MUST NOT change light propagation, which keeps its `u8` working grid.
- The light field is derived state and MUST NOT be saved.
- `LightSnapshot` MUST be built from direct lookups of the 3x3 footprint at and above
  `chunk.y - 1`, bounded by `CHUNK_COLUMN`, so a light job costs a constant number of chunk
  lookups. Missing chunks are air.

## 4. Level of detail

- `Lod` MUST gain `Lod2`, a 4x4x4 downsample.
- Desired LOD by distance in chunk units:
  - `Lod0` at or below `4`.
  - `Lod1` from `8`.
  - `Lod2` from `16`.
  - Between thresholds the current LOD is kept (hysteresis).
- LOD2 MUST emit every chunk-boundary face so LOD transitions cannot crack.
- The renderer MUST keep one buffer slot per LOD and select the active one per chunk.
- LOD selection and meshing MUST remain headlessly testable.

## 5. Streaming budgets

- At most two columns are committed to the world per frame.
- Generation requests MUST respect the worker pool admission rules; a refused request is retried on
  a later frame.
- Readiness MUST be tracked per loaded column, not reconstructed by rescanning every loaded column
  each frame.
- Per-frame metrics MUST report generated columns and their worker time.

## 6. Required tests

- Packed light: nibble round-trip for every value `0..=15`, halo edges at `-1` and `32`, and the
  existing cross-chunk propagation and mesh-lighting tests.
- The light snapshot footprint matches the v0.0.7 set for an interior column and for the top column.
- LOD2: downsample values, boundary faces, selection thresholds and hysteresis, and meshes at all
  three levels.
- Config: `8` and `32` accepted, `7` and `33` rejected.
- Streaming: a generation request that the pool refuses is retried, and readiness survives an
  update with no loaded-column change.

## 7. Acceptance

The scope's acceptance checklist and the roadmap's Definition of Done remain authoritative.
