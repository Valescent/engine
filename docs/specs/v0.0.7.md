# v0.0.7 spec: Advanced Horizons

**Status:** Shipped in v0.0.7.

**Normative:** This page is the technical contract for v0.0.7. The
[roadmap](../roadmap.md) owns milestone status and the Definition of Done, and the
[v0.0.7 scope](../dev/v0.0.7-scope.md) owns deliverables and acceptance criteria. This page
owns the seed and world files, deterministic generation, streaming, modified-chunk
persistence, and the optional renderer experiments. If the scope and this page disagree on a
technical detail, this page is authoritative and the scope is updated.

The keywords MUST, MUST NOT, SHOULD, and MAY are normative.

## 1. Scope

This spec covers:

- A persisted `u64` world seed.
- Five normalized noise fields and a deterministic generation pipeline.
- Four-chunk-tall terrain, sea level, three biomes, caves, water, and trees.
- A configurable render distance and streaming load/unload rules.
- Modified-only chunk persistence with `VCHK` v3.
- Generation, lighting, and meshing on the v0.0.5 worker pool.
- Optional `svdag` and `raymarch` feature-gated experiments.

Out of scope: multiplayer, networking, scripting, modding, content pipelines, weather,
seasons, fluid simulation, cross-chunk structures, GPU-side generation, and replacing the mesh
renderer.

## 2. Constants, blocks, and save format

- `CHUNK_SIZE = 32` remains.
- The world is 4 chunks tall: Y `0..=127`.
- `SEA_LEVEL = 32`.
- `Sand` is a new solid block with ID `8` and texture layer `10`.
- The texture array grows to 11 layers; layers `0..9` remain unchanged.
- `Block::layers` for Sand uses layer 10 on every face.
- `VCHK` version `3` is written. The loader MUST accept versions `1`, `2`, and `3`.
  - v1: block IDs `1..=5`; block count `1..=32768`.
  - v2: block IDs `1..=7`; block count `1..=32768`.
  - v3: block IDs `1..=8`; block count `0..=32768`.
- A v3 block count of `0` is valid only for an explicitly emptied modified chunk. v1 and v2
  still require at least one block.
- The v3 header and record layout remain the v0.0.4 layout; only the version, block IDs, and
  the empty-modified count are new.
- Light remains derived and is not saved.
- The v3 extension MUST be recorded in [ADR-0008](../decisions/0008-chunk-save-format.md) before
  implementation.

## 3. World files and seed

The world directory contains:

```text
world/
  seed
  chunks/
    chunk_{x}_{y}_{z}.vchk
```

`world/seed`:

- Contains one decimal `u64` and an optional trailing newline.
- Contains no other bytes or text.
- Is the same seed for every generated chunk in that world.
- Is not part of `config.toml`.

Creation rules:

- If `world/seed` is missing and no `.vchk` files exist, generate a random `u64` from OS
  entropy, write it, and use it for the new world.
- If `world/seed` is missing but `.vchk` files exist, abort with a typed error: the chunks
  cannot be regenerated safely.
- A malformed seed file is a typed error.
- The seed file MUST exist before the first chunk save.

## 4. Generation

### 4.1 Noise fields and determinism

[ADR-0012](../decisions/0012-fastnoise-lite-and-opensimplex2.md) selects `fastnoise-lite` 1.1.1
with OpenSimplex2 and pins its frequencies, octaves, seed mixing, normalization, and tree hash
before implementation.

Generation uses five normalized fields in `[0, 1]`:

- `continentalness(x, z)`
- `erosion(x, z)`
- `temperature(x, z)`
- `humidity(x, z)`
- `cave(x, y, z)`

Every field MUST be a deterministic function of `(seed, position)`. Generation MUST NOT use a
global RNG, global call order, or chunk load order. The same seed and coordinate MUST produce
the same result in any process.

### 4.2 Height, biomes, and surface

```text
height = clamp(1, 126, 32 + round((continentalness - 0.5) * 160
                                + (erosion - 0.5) * 32))
```

Biome priority:

1. `desert` when `temperature >= 0.65` and `humidity < 0.40`.
2. `hills` when `erosion <= 0.40`.
3. `plains` otherwise.

Surface columns:

| Biome | Surface |
|---|---|
| Plains | Grass at `height`; Dirt for three blocks below; Stone below. |
| Hills | Grass at `height`; Dirt for one block below; Stone below. |
| Desert | Sand for three blocks at `height`; Stone below. |

Water:

- When `height < SEA_LEVEL`, fill `y = height + 1 ..= SEA_LEVEL` with Water after caves.
- Water never replaces solid terrain.

Caves:

- Carve a solid cell to Air when `cave(x, y, z) > 0.60`, `y >= 1`, and `y <= height`.
- Carve before water fill.
- Cave carving may open the surface and create overhangs.

### 4.3 Trees

- Trees appear only in plains and hills.
- A chunk uses its deterministic `(seed, chunk coordinate)` hash to choose up to two candidate
  columns. [ADR-0012](../decisions/0012-fastnoise-lite-and-opensimplex2.md) pins the hash and
  candidate selection.
- A candidate requires:
  - The highest solid block in the column to be Grass.
  - The column above it to be Air, not Water.
  - The complete trunk and canopy to fit inside one 32×32×32 chunk.
- Trunk height is `4..=6` Wood blocks.
- The canopy is:
  - A 3×3 leaf plate at `top - 1`.
  - A 3×3 leaf plate at `top`.
  - A single leaf block at `top + 1`.
  - Trunk cells remain Wood.
- A candidate that would cross a chunk boundary or the world ceiling is skipped silently.
- Tree placement MUST NOT depend on chunk load order.

### 4.4 Spawn

- Scan `+X` from `x = 0, z = 0` for the first column with `height >= SEA_LEVEL` and a clear
  player AABB after generation. Trees or other features must not occupy the spawn volume.
- Spawn the player at `(x + 0.5, height + 1, z + 0.5)`, feet on the surface.
- The spawn column MUST be generated, lit, and meshed before movement is enabled.

## 5. Streaming

See [ADR-0013](../decisions/0013-player-centred-chunk-streaming.md) for the residency, hysteresis,
priority, and movement-guard decision.

### 5.1 Render distance

`config.toml` adds one key:

```toml
[world]
render_distance_chunks = 12
```

- Type: integer.
- Default when missing: `12`.
- Valid range: `8..=16`.
- Unknown keys and out-of-range values are typed configuration errors.
- The config path and precedence remain as documented in [Configuration](../dev/configuration.md).
- The key is read at startup; changing it requires a restart.

### 5.2 Load and unload

- The player's chunk is the chunk containing `Player::position`.
- A chunk column is a full vertical stack of four chunks with the same `(x, z)`.
- Load all columns with Chebyshev distance `max(|dx|, |dz|) <= render_distance`.
- Unload columns with Chebyshev distance `> render_distance + 2`.
- Every column is generated, lit, and meshed as four vertical chunks.
- A chunk with no stored blocks is empty air and needs no light or mesh.
- A column is visible only after all four chunks are generated, lit, meshed, and uploaded.
- At most two columns are committed to the world per frame.
- At most two chunk meshes are uploaded per frame, matching v0.0.5.
- The queue orders candidates by:
  1. Chunks in the forward half-plane first.
  2. Squared Euclidean distance from the player chunk.
  3. `(x, z)` ascending.
- Forward means `dot(normalize(chunk_center - player_position), horizontal_forward) >= 0`.

### 5.3 Unloaded-chunk guard

- A proposed axis movement MUST be rejected when the resulting player AABB would overlap a
  column that is not fully ready: generated, lit, meshed, and uploaded.
- Rejection zeroes that velocity component and leaves the player at the contact position.
- The current player column MUST remain ready.
- The guard applies to the v0.0.4 axis-separated movement.

### 5.4 Unload and fog

- Unloading saves a modified chunk before dropping it. If the save fails, the error is logged
  and the chunk remains in memory until the next save.
- Unloading releases CPU light data, GPU meshes, and water meshes, and cancels pending jobs.
- Stale results for unloaded chunks are discarded.
- The camera far plane becomes `(render_distance + 2) * 32` metres.
- Fog starts at `0.7 * render_distance * 32` metres and ends at `render_distance * 32` metres.
- The fog colour remains the v0.0.6 sky colour. This supersedes the v0.0.6 fixed `100 m` fog
  range.

## 6. Modified chunk persistence

- `Chunk` gains `modified: bool`.
- `World` also tracks a set of modified chunk coordinates, so an empty modified chunk remains
  known after its last block is removed and the empty `Chunk` is deleted.
- Generated chunks start unmodified.
- Player `set_block` marks the owning chunk modified. Generation and tree/feature placement
  MUST NOT mark chunks modified.
- Removing the last block from a modified chunk keeps its coordinate in the modified set and
  deletes the empty `Chunk` as usual.
- On unload and world save, every modified loaded chunk is written to `world/chunks`, including
  empty modified chunks.
- An empty modified chunk is written as a v3 file with `block_count = 0`.
- Unmodified chunks have no `.vchk` file.
- On load:
  1. If the file is v3 with `block_count = 0`, skip generation and load an empty modified
     chunk.
  2. Otherwise generate the chunk from the seed.
  3. If a `.vchk` file exists, apply its full block map over the generated blocks.
  4. Mark the chunk modified when a save file was applied.
  5. Recompute light and meshes.
- A v1/v2/v3 save file is applied the same way and marks the chunk modified.
- A save file that exists for a chunk overrides generation, even if its blocks match.
- A malformed, unsupported, or unreadable chunk file is a typed error. The world MUST NOT be
  partially loaded.
- `Ctrl+S` and clean exit save all loaded modified chunks.
- Save errors are typed and logged; they MUST NOT panic.
- Light is never written to disk.
- The seed file and chunk files MUST be written under the same world directory.

## 7. Worker integration

- Generation runs on the v0.0.5 worker pool, alongside light and mesh jobs.
- A generation job receives the seed and chunk coordinate; it MUST NOT read mutable engine
  state.
- The main thread applies completed generation results, marks visibility only after lighting
  and meshing, and performs all GPU uploads.
- Edits remain urgent. Background generation and remeshing are lower priority.
- Revisions, stale-result rejection, bounded queues, and the two-mesh upload budget from
  v0.0.5 remain.
- Metrics add generation time and queue depth to the v0.0.5 frame metrics.

## 8. Optional experiments

Two Cargo features are optional and MUST default off:

- `svdag`: compressed representation for far or static chunks; the existing mesh path remains
  the reference and default.
- `raymarch`: alternate GPU raymarching renderer; it MUST NOT replace the mesh path by default.

Neither feature is part of v0.0.7 acceptance. Both MUST be feature-gated and MUST NOT
destabilise the default renderer or default test suite.

## 9. Required tests

CPU-only tests MUST cover:

- Seed file creation, parsing, malformed input, and missing-seed-with-chunks errors.
- Same seed and coordinates produce identical height, biome, cave, surface, water, and tree
  output.
- Generation independent of load order and worker completion order.
- Height clamping, sea level, biome thresholds, surface palettes, caves, and trees that fit.
- Spawn column selection above sea level.
- Render-distance config default, range validation, and unknown-key rejection.
- Chebyshev load/unload rings and the forward/distance tie order.
- Player guard rejects movement into a not-ready column.
- Modified chunk saves only after edits; unmodified chunks have no file.
- A fully cleared modified chunk saves a v3 `block_count = 0` file and reloads empty instead
  of regenerating.
- Generate-then-apply for v1, v2, and v3 files; Sand round-trips in v3.
- Unload saves modified chunks and stale jobs are discarded.
- Light and water recompute after generation and load.
- Optional features are off by default and do not alter the default renderer.

Manual GPU acceptance remains in the [v0.0.7 scope](../dev/v0.0.7-scope.md#acceptance-checklist)
and [Testing](../dev/testing.md). The scope's acceptance checklist and the roadmap's Definition
of Done remain authoritative for milestone completion.
